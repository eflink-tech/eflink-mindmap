# 硬约束（违反会产生"预览正常但编辑器不对"或结构错乱）

## 1. 忠实原图层级，不发明结构

- 逐支对照原图：**一个分支不漏、一级不多**。实在数不清的密集子节点宁可整支省略并在交付说明里注明，也不要猜结构编造节点。
- 原图同层节点的**顺序**就是 children 数组顺序（布局按数组顺序排），左右侧导图先右后左或按
  原图从上到下顺序写，`side` 显式标注。

## 2. 文本纪律

- 节点 text 是短语不是句子：一级 ≤15 字、深层 ≤20 字；超长说明放 `note`。
- 换行只用 `\n`；不要 HTML、不要首尾空格。
- 原图水印/广告字样（"ProcessOn"、"模板"角标等）一律忽略。

## 3. 双侧布局必须标 side

原图是根居中、左右两侧展开的导图（大多数 ProcessOn 导图模板）时，**每个一级分支都要写
`side`**（"left"/"right"），按原图实际左右归属——不标会按"少的一侧优先"自动分侧，
与原图左右相反时整图观感就错了。单侧布局（logic/org/timeline 等）不写 side。

需要某个分支单独改向（如双侧导图里一支向上）时，在该一级分支上写 `branchDirection`
（left/right/up/down），仅 map/logic/org/tree 生长方向布局生效。

## 4. 配色用主题，不逐节点涂色

- 90% 的模板选对 `themeId` 就还原了（`rainbowBranches` 自动逐分支上色）。
- **编辑器语义**：二级节点浅底 = 主题分支色 tint 85%，三级及更深 = 纯文字无底色；
  分支色按根 children 的**原始序号**取（左右两侧共用一个色序）。一级节点手写
  `style.fillColor` **不会**传导给子级底色——所以同色系原图（如全薄荷绿）也直接选
  最接近的主题即可，逐节点涂色费力且子级不跟随。
- 逐节点 `style.fillColor` 仅用于单个节点需要跳出色系的强调色。
- 文字颜色不需要写：主题会按底色明暗自动黑/白；只有原图明确反色才写 textColor。

## 5. 标记与装饰

- 原图的优先级图标（!、数字旗）→ `markers.priority`；对勾/进度 → `task`；旗帜 → `flag`；星星 → `star`。
- 贴纸/插画/背景装饰**不采**（编辑器无对应原生对象，硬塞 emoji 会失真）。
- emoji 表情在原图节点文字里的可以直接保留在 text 里。

## 6. 规模上限

- 单图 ≤300 节点（超出转换器警告）；层级 ≥8 层的"线性长链"检查是否把时间轴误判成了导图。
- 时间轴/鱼骨/矩阵也是"根→一级→二级"的树，spec 写法相同，别被原图的几何形态带偏去发明字段。

## 7. 自检必须做

转换产出 `.svg` 预览 → Chrome headless 截 PNG → Read 检查：
- 层级数对、分支数对、无文字截断（预览文字按粗略字宽排，编辑器里更宽松）
- 双侧图的左右归属与原图一致
- 配色主题观感与原图接近
发现问题改 spec 重转，别交付没自检过的产物。
